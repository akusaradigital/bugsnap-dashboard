# Anti-Slop Human / Accessibility Audit #002 (2026-10-14)

Project: `bugsnap-dashboard`
Auditor: Anti-Slop Human Filter (Mode 2 — AFTER)
Concern: Human / Accessibility (Contrast, Keyboard, Focus, ARIA, Screen Readers, States)
Framework: Next.js 14 / Tailwind CSS

---

## Findings Summary

This audit evaluates all user interfaces and components in `bugsnap-dashboard` against `antislop-human` rules (R-25 Contrast, R-32 Keyboard Accessibility, R-34 Focus Indicators, R-27 UI States, C-4 Craftsmanship) and WCAG 2.1 AA standards.

| No | Category / Rule | Target File | Priority | Rationale & Accessibility Impact |
|---|---|---|---|---|
| 1 | **R-25 (Low-Contrast Text)** | `src/app/page.tsx`, `src/components/site/PillTabs.tsx`, `src/app/features/FeaturesContent.tsx`, etc. | **HIGH** | Category/eyebrow text uses green `--accent` (`#89BD49`) on white backgrounds (`#FFFFFF`) with a contrast ratio of only **2.22:1** (fails WCAG AA 4.5:1 minimum for normal text). |
| 2 | **R-25 (Low-Contrast Text)** | `src/app/globals.css` (line 10) | **HIGH** | Secondary text token `--muted: #64748b` on `--background: #f3f4f6` in light mode yields **4.32:1** (fails 4.5:1 minimum for normal dashboard text). |
| 3 | **R-25 (Text on Hover)** | `src/components/site/SiteNavbar.tsx` (line 111) | **HIGH** | Desktop and mobile navigation links use `hover:bg-accent-hover hover:text-white`. White text on `#6B9A35` provides a contrast ratio of only **3.33:1** (fails 4.5:1 threshold). |
| 4 | **R-32 (Removed Focus Outline)** | `src/components/Dropdown.tsx` (line 22) | **HIGH** | Primary dropdown trigger button uses `outline-none` without replacement focus indicator (`focus-visible:ring`). Keyboard users (Tab) cannot locate the focused element. |
| 5 | **R-32 (Removed Focus Outline)** | `src/app/help/HelpContent.tsx` (line 46) | **HIGH** | FAQ accordion buttons use `focus:outline-none` without replacement focus rings. |
| 6 | **R-32 & WCAG 2.4.1 (Skip Link)** | `src/components/site/SiteNavbar.tsx`, `src/app/(app)/layout.tsx`, `src/app/admin/layout.tsx` | **HIGH** | Missing "Skip to main content" bypass block links. Keyboard navigators must repeatedly tab through headers and menu bars before reaching primary content. |
| 7 | **R-32 & WCAG 2.1 (Escape Key)** | `src/components/site/SiteNavbar.tsx` (lines 148-185) | **MEDIUM** | Open mobile navigation drawer lacks an `Escape` key event listener to close the drawer and restore focus to the trigger button. |
| 8 | **R-34 & WCAG 4.1.2 (ARIA Expanded)** | `src/app/pricing/PricingToggle.tsx`, `src/app/page.tsx`, `src/app/admin/layout.tsx` | **MEDIUM** | FAQ accordion triggers and admin panel dropdowns omit `aria-expanded` and `aria-controls` attributes, preventing screen readers from announcing toggle states. |
| 9 | **WCAG 4.1.2 (Unlabeled Icon Buttons)** | `src/app/(app)/captures/page.tsx`, `src/app/admin/layout.tsx` | **MEDIUM** | Pure icon buttons (such as upload dismiss `lucide:x`, sidebar toggle `lucide:menu`) lack accessible `aria-label` descriptors for screen readers. |
| 10 | **R-03 / CSS Token Integrity** | `tailwind.config.ts`, `src/app/globals.css` | **LOW** | Utility classes `text-site-accent`, `bg-site-accent/10`, and `border-site-accent/20` used in 11 files are undefined in `tailwind.config.ts` and `globals.css`, causing styles to be ignored. |
